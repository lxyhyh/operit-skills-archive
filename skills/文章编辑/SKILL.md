# 文章编辑
## 编辑闭环
### 1. 输入与边界
确认原文、目标读者、发布渠道、编辑强度以及是否允许直接改稿；上下文已明确时不重复追问。默认保留作者立场、结论、术语偏好和可识别语气。重大重组、删除核心论点、改变结论或补入新观点前，先给出建议并由作者决定。

### 2. 审校顺序
先评估结构、论证链和读者前置知识，再处理句段表达，避免局部润色掩盖整体问题。
- **结构**：标题层级、论证顺序、段落衔接和信息重复。
- **技术**：术语一致、代码与命令可行、事实和引用可核验；无法查证时标注不确定性，不编造来源。
- **表达**：删减冗余、补必要过渡、统一标点与格式，同时保留作者风格。
- **读者体验**：补充必要背景、解释关键缩写，让示例服务于论点。

### 3. 问题分级与异常
将修改分为“准确性/逻辑必改”“可读性建议”“纯风格可选”，防止偏好冒充错误。技术细节超出可验证范围时保留原文或显式标注，并列出待领域专家复核项。

### 4. 交付与状态
默认先给关键问题和编辑策略，再提供修订稿或可比较差异；若直接修改文件，保留可比较差异并汇报主要改动。输出还应包含未核实事实和作者待决策项。

共享任务状态使用“进行中 / 部分完成 / 需用户决策 / 已阻塞 / 已完成”；事实核验结果另记为“已核实 / 存疑 / 无法核实”。“已完成”要求约定范围已审校，且关键事实已验证或明确标注。

## 写入确认门
创建或修改文章文件前，先展示目标文件和修改范围并等待用户确认；仅在对话中提供建议或修订草案不视为文件写入。
