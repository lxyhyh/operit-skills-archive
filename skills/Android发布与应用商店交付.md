# Android发布与应用商店交付

## 使命

收口 Android 签名、制品、商店资料、合规检查和分阶段交付。 本技能是纯指导型工作框架：Trae 应读取项目事实、现有约束和可用工具后自主选择分析方法、参数、工具与执行顺序，而不是机械套用固定命令。

## 适用情形

当任务涉及版本与制品、签名边界、商店政策、素材清单、轨道发布、监控回退时启用。若请求主要属于其他专业技能，应说明边界并转交，不重复制造相互冲突的结论。

## 工作原则

- 签名即身份：签名密钥的保管、轮换和撤销策略优先于构建自动化；丢失密钥控制权等于丧失应用所有权。
- 商店合规前置：在构建前验证权限声明、隐私标签、内容分级和导出限制，不在提交被拒后补救。
- 分阶段交付：内部测试→封闭测试→开放测试→生产发布，每个阶段有独立的质量门槛和回滚方案。
- 制品可追溯：每个发布制品必须可从构建日志追溯到源代码提交，构建环境信息与签名证书指纹。

## 工作流程

### 1. 确认发布范围与约束

确定目标版本、渠道（Google Play/厂商/企业分发）、合规要求、内容分级和地区限制。

### 2. 检查签名与构建配置

验证签名密钥可用性、buildType/flavor 配置、ProGuard/R8 映射保留、原生库的 ABI 对齐。

### 3. 构建与验证制品

生成签名 APK/AAB，验证签名有效性、权限清单、AndroidManifest 完整性、动态功能模块配置。

### 4. 商店资料与合规审查

检查应用描述、截图、隐私政策链接、数据安全标签与实际情况一致；验证 API 级别目标和依赖库的商店政策兼容性。

### 5. 分阶段发布与监控

按阶段推送制品，监控崩溃率、ANR、启动时间、评价变化，设定回滚触发阈值和回滚流程。
## 用户确认边界

遇到关键需求歧义、不可逆或破坏性操作、生产环境写入、敏感权限或秘密、外部发布、费用承诺、法律与业务风险取舍时，必须暂停并请求用户或责任人明确确认。普通的只读检查、可逆分析和已授权范围内的实现由 Trae 自主推进，避免对每个细节反复询问。

## 专项边界

不索取或保存真实签名秘密；商店提交、签名变更和正式发布必须获得授权。

## 路由与协作

可将专项工作转交给：CI-CD与发布管理、测试策略与质量保障、隐私合规与数据治理、线上可观测性与事故响应。默认将上述技能作为专项协作方，当前主技能保留目标、进度和最终验收责任。只有当前技能已不再适合承担主目标时才切换主技能；切换或协作时提供上下文、已验证事实、未决问题、风险等级、期望输出和返回条件。协作结果返回当前主技能验收；没有新增证据或状态变化时不得重复转交。

## 状态模型

每项工作只能以以下状态之一汇报：已完成 / 部分完成 / 已阻塞 / 需用户决策 / 已转交 / 无法验证。状态后必须附证据或阻塞原因；“已完成”要求验收条件已经被验证，“无法验证”必须说明所缺环境、权限或数据。

## 完成标准

- 范围、假设、事实和决策边界清楚。
- 高风险事项有处置、接受、转交或明确阻塞结论。
- 关键结论具备可复核证据，验证与回退方式匹配风险。
- 未决事项具有负责人、触发条件或下一步，不用模糊措辞掩盖不确定性。
- 发布制品的签名指纹、构建来源和合规声明已记录并可审计。
- 每一阶段的崩溃率/ANR 阈值和回滚触发条件已经量化设定。
