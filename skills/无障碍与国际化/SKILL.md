# 无障碍与国际化

## 使命

确保产品对不同能力、语言、地区和文化背景的用户可达且可理解。 本技能是纯指导型工作框架：Trae 应读取项目事实、现有约束和可用工具后自主选择分析方法、参数、工具与执行顺序，而不是机械套用固定命令。

## 适用情形

当任务涉及语义与导航、视觉听觉、输入反馈、辅助技术、本地化、地区格式与布局时启用。若请求主要属于其他专业技能，应说明边界并转交，不重复制造相互冲突的结论。

## 工作原则

- 无障碍是可用性问题，不是功能：不可操作的界面、不可读的内容是不可接受的缺陷，处理等级等同于功能 bug。
- 国际化不止翻译：日期/数字/货币格式、排序规则、文本方向（RTL）、字符编码和时区处理是国际化的基础。
- 设计与实现同时检查：无障碍缺陷可能在设计（对比度、导航顺序）和实现（语义标记、焦点管理）两个层面产生。
- 辅助技术验证：自动化测试不能替代屏幕阅读器、键盘导航和缩放测试的实际操作验证。

## 工作流程

### 1. 审查当前状态

扫描界面组件的语义标记、焦点顺序、对比度、可缩放性；检查 i18n key 覆盖率和硬编码文本。

### 2. 识别缺陷与风险

按 WCAG 等级（A/AA/AAA）和 i18n 缺失（硬编码/未翻译/格式错误）分类列出问题。

### 3. 制定改进计划

按用户影响和修复成本排序；区分 Quick Win 和需要架构调整的长周期改进。

### 4. 实施修复

修复代码和设计，添加语义标记、ARIA 属性、i18n 资源和格式化逻辑。

### 5. 验证

使用屏幕阅读器、键盘导航和缩放测试验证修复；检查不同语言下的布局和格式。
## 用户确认边界

遇到关键需求歧义、不可逆或破坏性操作、生产环境写入、敏感权限或秘密、外部发布、费用承诺、法律与业务风险取舍时，必须暂停并请求用户或责任人明确确认。普通的只读检查、可逆分析和已授权范围内的实现由 Trae 自主推进，避免对每个细节反复询问。

## 专项边界

不以自动扫描替代辅助技术和真实用户体验；不假定语言、阅读方向或地区格式。

## 路由与协作

可将专项工作转交给：测试策略与质量保障、技术文档与知识治理、产品分析与实验治理。默认将上述技能作为专项协作方，当前主技能保留目标、进度和最终验收责任。只有当前技能已不再适合承担主目标时才切换主技能；切换或协作时提供上下文、已验证事实、未决问题、风险等级、期望输出和返回条件。协作结果返回当前主技能验收；没有新增证据或状态变化时不得重复转交。

## 状态模型

每项工作只能以以下状态之一汇报：已完成 / 部分完成 / 已阻塞 / 需用户决策 / 已转交 / 无法验证。状态后必须附证据或阻塞原因；“已完成”要求验收条件已经被验证，“无法验证”必须说明所缺环境、权限或数据。

## 完成标准

- 范围、假设、事实和决策边界清楚。
- 高风险事项有处置、接受、转交或明确阻塞结论。
- 关键结论具备可复核证据，验证与回退方式匹配风险。
- 未决事项具有负责人、触发条件或下一步，不用模糊措辞掩盖不确定性。
- 缺陷已标注 WCAG 等级，Blocker 级别的无障碍缺陷已修复或获得明确接受。
- 新界面/新语言的 i18n 覆盖率已达到项目约定阈值（读取项目配置，无配置时以 >90% 为建议值）。
