# 架构改进
## 改进闭环
### 分析输入
读取模块边界、依赖图、变更热点、缺陷记录、测试 seam、`CONTEXT.md`、相关 ADR 和性能数据。报告必须把观察事实与设计判断分开；没有代码或运行证据时不得给模块打确定性分数。

### 选择与实施
1. 识别接口膨胀、职责泄漏、循环依赖、重复策略和错误 seam。
2. 对每项机会给出收益、影响范围、迁移成本、兼容策略和不改的后果。
3. 生成决策用报告；报告本身不自动触发批量重构。
4. 用户选择后按可回退的纵向切片实施，每个切片保持约定外部行为并通过接口级回归测试。
5. 新术语或稳定边界按需回写 `CONTEXT.md`；关键不可逆取舍按需记录 ADR。

### 报告形式
报告可以是 Markdown、HTML 或用户指定格式。若使用 HTML，应自包含并优先写入系统临时目录，不污染仓库。每个候选包含：涉及模块、事实证据、问题、方案、收益、迁移风险、前后关系图和推荐强度。

### 交付与二层状态
输出分析报告、优先级建议、用户选定项、实际变更、验证证据和剩余风险。
- 共享任务状态：`进行中 / 部分完成 / 需用户决策 / 已阻塞 / 已完成`。
- 领域阶段：`分析中 / 报告已生成 / 候选已选择 / 实施中 / 复验完成`。
仅生成报告时，若当前约定交付物就是分析报告，共享任务可标为已完成且领域阶段为“报告已生成”；若整体目标包含代码改进，则共享状态应为部分完成或需用户决策，不能称为整体改进已完成。

## 用户确认门
生成大范围报告文件、实施跨模块重构、移动公共接口、删除代码或更新项目知识文件前，先展示目标路径、候选方案、影响范围和验证/回退计划并等待用户确认。只读扫描和在对话中展示候选不需要写入确认。

## 协作与返回
`代码设计`提供架构词汇，`领域建模`维护领域边界，`功能实现`或 `TDD开发`可承担获批切片。专项协作结果必须返回本技能，由本技能保留整体进度和最终验收责任；只有核心目标转变时才切换主技能。
