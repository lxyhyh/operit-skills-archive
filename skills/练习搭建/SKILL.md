# 练习搭建
## 练习契约
### 输入
读取课程目标、学习者前置知识、章节顺序、目标媒介或技术栈、运行环境和答案开放策略。每个练习必须对应明确学习目标，不用固定目录数量代替教学价值。

### 结构选择
目录与文件结构由教学媒介决定，不强制所有课程采用 `problem/solution/explainer`、TODO、stub README 或 lint：
- 编程练习可包含学员起始文件、测试、提示、参考解法和讲解；
- 问答、写作、设计或操作型练习可使用题目、素材、评分量规、示例答案或复盘；
- 交互式平台可使用平台约定的元数据与入口文件；
- 项目已有课程规范时优先遵循，并记录与通用结构的差异。
答案或评分细则按开放策略与学员起始材料隔离，避免默认泄露。

### 单题最小定义
每个练习至少明确：学习目标、任务、输入或素材、预期可观察结果、约束、提示策略和评判方式。不适用字段可以省略，但应保证学习者知道如何开始、如何判断完成。

## 工作流
1. 解析教学计划，提取章节、练习、依赖顺序和目标能力。
2. 根据媒介与仓库规范提出目录树、命名规则和文件职责。
3. 展示将创建、跳过或可能冲突的文件，以及答案隔离方式。
4. 用户确认后创建内容；不覆盖已有作答，冲突时提供跳过、合并或新版本选项。
5. 执行与媒介相符的验证并记录证据。

## 验证策略
验证应与练习类型匹配：
- 可执行练习：检查起始状态可运行或可按说明启动、目标解法可通过、代表性错误能被测试或评判规则识别；
- 非可执行练习：检查说明完整、素材可访问、评分量规与学习目标一致，并抽样走通完成路径；
- 当前环境无法验证时，说明缺失工具、未验证项、风险和复验命令，不虚报通过。

## 交付与状态
输出目录树、创建/跳过/冲突文件、验证结果、答案可见性和未完成章节。共享任务状态使用“进行中 / 部分完成 / 需用户决策 / 已阻塞 / 已完成”；搭建结果另记为“结构已生成 / 内容已填充 / 验证受限”，不替代共享状态。

## 用户确认门
创建目录树或批量写入练习、测试、素材与答案文件前，先展示完整文件计划、覆盖策略和验证方式并等待用户确认。
