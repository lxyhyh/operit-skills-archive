# 自动编译

## 目标
根据项目现场完成一次可解释、可验证的构建。Skill 提供判断标准；具体工具、命令、参数、并行方式和执行顺序由 Trae 决定，不以固定命令表替代项目自身约定。

## 原则
- **项目优先**：先读 README、贡献指南、CI、构建脚本、wrapper、lockfile 和项目配置，再判断项目类型与入口。
- **先查后装**：优先复用项目声明的工具链。安装依赖、修改系统环境或全局配置前说明影响，并按授权边界确认。
- **动态监控**：是否设置超时及其范围，由任务类型、项目规模、缓存状态、历史耗时、网络与资源状况决定；应能终止失控任务并保留诊断信息。
- **风险驱动验证**：是否运行测试以及测试范围由变更风险、项目约定和用户目标决定，不默认跳过，也不无差别运行全部验证。
- **可解释执行**：可以使用安全且错误语义清晰的命令组合、脚本或构建工具任务图；避免因串联掩盖失败状态或造成不可控副作用。

## 工作流
1. **识别构建入口**：处理多模块、多生态或生成式项目时，识别真正交付目标及依赖关系；不只按首个特征文件猜测。
2. **核查工具链**：比对项目声明与实际运行时、包管理器、SDK、编译器、环境变量和权限。版本选择来自项目配置及兼容关系。
3. **选择构建与验证范围**：优先项目脚本、wrapper 和 CI 同源命令。根据目标选择编译、打包、类型检查、相关测试或冒烟验证的最小充分集合。
4. **执行和观察**：记录关键命令、退出状态、日志摘要、耗时和产物。独立的只读检查可并行；有依赖或副作用的步骤按因果关系组织。
5. **处理失败**：先保留原始错误和环境快照，再区分依赖下载、工具链兼容、资源、配置、代码或测试失败。只做能验证假设的可逆调整，避免盲目清缓存、升级或反复重跑。
6. **验证交付物**：确认目标产物存在、类型和位置合理，并按风险执行相关测试或最小运行验证。

## 路由
- Android/APK 构建卡住或构建系统异常：**APK编译问题诊断**。
- 缺少 Android 系统级工具链：**Android开发环境搭建**。
- 根因不清、跨组件或性能回归：**调试诊断**。
- 根因明确且需修改代码：**Bug修复**。

## 用户确认边界
局部、可逆且在既有授权内的构建操作由 Trae 自主执行。安装/卸载系统组件、修改全局环境、删除大范围缓存或产物、使用敏感凭据、产生费用、发布或上传产物前，展示影响与回退方式并等待确认。

## 主责任与返回闭环
自动编译保留构建任务的主责任。调用 `Android开发环境搭建`、`APK编译问题诊断`、`调试诊断` 或 `Bug修复` 时，记录原始构建命令、环境快照、失败证据和预期返回条件。协作完成后返回本技能，以相同目标和可比环境重跑原失败路径；“环境已安装”“根因已定位”或“代码已修改”都不等于构建恢复。多轮协作仍失败时停止无信息增益的重试，输出已排除项和残余阻塞。

## 交付状态
输出项目类型与入口、原始及复验命令、环境、产物、验证证据、失败分类、协作记录、未验证项及下一步。状态使用“已完成 / 部分完成 / 已阻塞 / 需用户决策 / 已转交 / 无法验证”；“已完成”要求目标产物和约定验证均通过。
