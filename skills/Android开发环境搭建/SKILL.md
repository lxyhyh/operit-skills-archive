# Android开发环境搭建

## 原则
- **有项目按项目**：读取 wrapper、AGP、Kotlin、compileSdk、构建脚本、版本目录和 CI；版本选择来自项目声明与官方兼容关系。
- **无项目按目标**：先确认计划创建或构建的项目类型，再选择相互兼容且受支持的工具链，不硬编码通用版本。
- **先检查再安装**：复用可用组件，区分必需、可选和项目专用组件。
- **局部优先、可逆优先**：优先 wrapper、项目配置和用户目录，避免无依据覆盖全局环境、镜像或已有配置。

## 工作流
1. **识别环境**：操作系统/架构、shell、权限、磁盘/内存、网络/代理，以及现有 JDK、SDK、构建工具和环境变量。
2. **读取项目约束**：确认真实构建入口和所需 JDK、Gradle/AGP、SDK Platform、Build Tools、NDK/CMake 等。仅安装项目实际需要的组件。
3. **形成差距清单**：标记“已满足 / 缺失 / 不兼容 / 可选 / 信息不足”，并说明证据和预计影响。
4. **按需补齐**：Trae 根据系统包管理器、官方渠道、可信镜像和项目约定选择方式；下载校验依据发布方提供的校验值或签名，不以固定文件大小代替完整性验证。
5. **配置隔离**：修改环境变量、代理、镜像和缓存时先检查既有配置，避免重复、冲突和泄露凭据。项目专用设置尽量留在项目或明确的用户级配置中。
6. **最小验证**：先验证工具可发现及版本兼容，再运行项目 wrapper/配置检查，最后按项目能力执行最小构建或任务枚举。构建异常转 **APK编译问题诊断**。

## 动态资源与超时
空间、内存、下载和构建等待策略应结合组件规模、项目历史耗时、网络和设备资源判断。发现资源不足时报告所需与现状，不使用固定阈值直接宣告所有项目不可执行。

## 用户确认边界
只读检查可自主执行。安装/卸载系统组件、使用管理员权限、修改全局环境或 shell 启动文件、覆盖既有 Gradle/SDK/代理/镜像配置、大范围清缓存、接受许可证或下载产生明显费用前，列出变更、作用域、风险和回退方式并等待确认。项目内已授权且可逆的小范围配置可自主处理。

## 输出
给出环境清单、版本依据、实际变更、验证结果、未安装的可选项和后续路由。状态使用"已完成 / 部分完成 / 已阻塞 / 需用户决策 / 无法验证 / 已转交"。

## 停止条件与返回
- 所有必需组件已验证通过 → 已完成，返回触发源（APK编译问题诊断或自动编译）复验。
- 部分组件无法安装但有替代方案 → 部分完成，标注阻塞项和替代路径。
- 权限不足、网络不可达或版本冲突无法解决 → 已阻塞，记录具体原因和所需授权。
- 完成后必须通知源技能重新运行原构建/检查命令验证环境是否满足要求。状态使用“已完成 / 部分完成 / 已阻塞 / 需用户决策 / 无法验证 / 已转交”。
