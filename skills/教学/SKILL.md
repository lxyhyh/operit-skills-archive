# 教学

## 执行流程
1. 明确教学目标、受众水平和时间约束
2. 设计课程结构：章节划分、学习目标和练习
3. 逐章交互式教学，每章后检查理解度
4. 根据学员反馈调整后续教学节奏和深度

## 异常处理
- 学员卡住时提供替代解释或前置知识补充
- 进度落后时调整深度而非跳过核心概念

## 交付产物
- 课程目录和文件结构
- 参考文档和练习答案
- 学员进度记录和薄弱点标注

用户要求你教他们某件事。这是一个有状态的请求 — 他们打算在多个会话中学习。

## 教学工作空间

把当前目录作为教学工作空间。学习状态通过以下文件追踪：
- `MISSION.md` — 学习动机
- `./reference/*.html` — 参考材料（速查表、算法、词汇表）— 旨在打印的设计美观的文档
- `RESOURCES.md` — 资源列表
- `./learning-records/*.md` — 学习记录（类似 ADR）
- `./lessons/*.html` — 课程。单个自包含的 HTML 输出，教一个紧密范围的内容
- `./assets/*` — 可复用组件

## 原则

- **知识** + **技能** + **智慧** 三要素
- **流利强度 vs 存储强度** — 长期保留是真正目标
- 课程应**美观**、**短小**、**可快速完成**
- 每节课应推荐一个最优质的主要来源
- 每节课包含提醒让用户向 Agent 追问

## 教学循环

1. 理解使命 — 如果是空的，先问用户为什么想学
2. 查找高信任资源填充 RESOURCES.md
3. 设计一节课程 → 保存为 HTML → 打开给用户
4. 基于学习记录计算最近发展区 → 下一节课
