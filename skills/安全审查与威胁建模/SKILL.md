# 安全审查与威胁建模

## 使命

识别信任边界、攻击面和滥用路径，形成可验证的风险处置建议。 本技能是纯指导型工作框架：Trae 应读取项目事实、现有约束和可用工具后自主选择分析方法、参数、工具与执行顺序，而不是机械套用固定命令。

## 适用情形

当任务涉及资产与信任边界、威胁场景、风险分级、安全控制、验证证据、剩余风险时启用。若请求主要属于其他专业技能，应说明边界并转交，不重复制造相互冲突的结论。

## 工作原则

- 信任边界决定一切：所有分析从明确信任边界开始；跨边界的数据流、认证和授权是审查的强制焦点。
- 攻击面最小化：识别并减少不必要的接口、端口、权限和数据暴露；每增加一个端点或权限都需要安全理由。
- 威胁可操作：每个识别到的威胁必须有具体攻击路径、前置条件、影响和缓解方案；不列模糊的"可能被攻击"。
- 纵深防御：不在单点依赖安全控制；假设每一层防护都可能失败，设计多层检测和遏制。

## 工作流程

### 1. 定义审查范围与信任边界

确定系统边界、用户角色、数据流和外部依赖；以数据流图或架构图标注信任域。

### 2. 威胁识别

按 STRIDE（欺骗/篡改/抵赖/信息泄露/拒绝服务/权限提升）或攻击树逐边界枚举威胁。

### 3. 风险评估与排序

对每个威胁评估利用难度、影响等级、发现可能性；按风险矩阵排序。

### 4. 设计缓解方案

为高风险威胁设计具体缓解：预防（认证/授权/加密）、检测（日志/告警）、响应（阻断/降级/取证）。

### 5. 输出安全报告

交付威胁清单、缓解建议、残余风险和验证方法；高风险未缓解项必须有明确接受者。
## 用户确认边界

遇到关键需求歧义、不可逆或破坏性操作、生产环境写入、敏感权限或秘密、外部发布、费用承诺、法律与业务风险取舍时，必须暂停并请求用户或责任人明确确认。普通的只读检查、可逆分析和已授权范围内的实现由 Trae 自主推进，避免对每个细节反复询问。

## 专项边界

不执行未授权攻击性测试，不接触或保存真实密钥，不把合规检查等同安全证明。

## 路由与协作

可将专项工作转交给：Bug修复、依赖升级与技术债治理、身份认证与权限设计、隐私合规与数据治理。默认将上述技能作为专项协作方，当前主技能保留目标、进度和最终验收责任。只有当前技能已不再适合承担主目标时才切换主技能；切换或协作时提供上下文、已验证事实、未决问题、风险等级、期望输出和返回条件。协作结果返回当前主技能验收；没有新增证据或状态变化时不得重复转交。

## 状态模型

每项工作只能以以下状态之一汇报：已完成 / 部分完成 / 已阻塞 / 需用户决策 / 已转交 / 无法验证。状态后必须附证据或阻塞原因；“已完成”要求验收条件已经被验证，“无法验证”必须说明所缺环境、权限或数据。

## 完成标准

- 范围、假设、事实和决策边界清楚。
- 高风险事项有处置、接受、转交或明确阻塞结论。
- 关键结论具备可复核证据，验证与回退方式匹配风险。
- 未决事项具有负责人、触发条件或下一步，不用模糊措辞掩盖不确定性。
- 每个高风险威胁已有具体缓解方案或被明确接受的残余风险记录。
- 信任边界和数据流已文档化，新增端点/权限/数据暴露已在审查范围内。
