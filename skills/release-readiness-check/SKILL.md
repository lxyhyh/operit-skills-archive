# 发布前就绪检查

## 适用范围

- 用于**正式/生产环境发版前**的就绪核验，或发版计划中的一次正式检查。
- 不用于：代码编写与修复本身（那是开发/修复技能的事）；也不替代运维的实际执行操作。

## 判定标准

逐项核验，每一项给出**证据 + 结论**（通过 / 不通过 / 待确认）：

1. **构建**：目标产物能否在当前主干/候选版本上干净构建（CI 是否绿、有无人工跳过）。
2. **测试**：关键测试套件（单测/集成/E2E）通过情况；覆盖本次变更的风险点是否有测试。
3. **变更范围**：本次版本实际包含哪些 commit/模块，是否与计划一致，有无夹带无关改动。
4. **兼容与迁移**：涉及数据库/配置/API/依赖时，迁移脚本就绪、可回滚，前后端/下游兼容已核验。
5. **回滚预案**：明确回滚方式（版本回退/开关/数据回滚），负责人与演练情况。
6. **监控与告警**：关键指标、日志、告警阈值在发版后可见；异常时的退路已明确。
7. **文档与通知**：变更说明（changelog/release notes）、使用者通知、值班安排已就绪。
8. **合规与安全**：涉及的数据合规、权限变更、密钥/凭据管理已核验；无高危漏洞未处理。

## 作答规范

输出固定三段，证据与判断分离：

1. **结论**：可发版 / 有条件发版（列出必须满足的前置条件）/ 不可发版（列出阻塞项）。
2. **逐项核验表**：8 项标准 × 证据 / 结论；不通过或待确认项标明原因与负责动作。
3. **风险与建议**：按严重度排序的剩余风险、发版窗口建议、以及"发版后 24h 内需盯的指标"。

每个"不通过"必须给出证据来源（构建号、测试名、文件、配置项），不凭印象给结论。

## 边界

- 只做检查与判断，**不执行发版、不改代码、不发布**；需要实施时由用户或对应技能执行。
- 证据不足的项标为"待确认"，不强行给通过/不通过。
- 一次只评估一个目标版本，不混入多个版本的对比建议（除非用户要求）。
- 不扩大范围：与本次发版无关的历史遗留问题只记录不展开。
