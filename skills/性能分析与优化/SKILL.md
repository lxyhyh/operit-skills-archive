# 性能分析与优化

## 使命

通过可重复测量、假设验证和基准对比定位并改善性能瓶颈。 本技能是纯指导型工作框架：Trae 应读取项目事实、现有约束和可用工具后自主选择分析方法、参数、工具与执行顺序，而不是机械套用固定命令。

## 适用情形

当任务涉及性能目标、基线、采样与追踪、瓶颈假设、实验设计、回归防护时启用。若请求主要属于其他专业技能，应说明边界并转交，不重复制造相互冲突的结论。

## 工作原则

- 测量优于猜测：任何优化必须以可重复的性能测量为起点；不经测量的优化是随机修改。
- 瓶颈驱动优化：聚焦在最慢的环节（90th/99th 百分位延迟、最大吞吐量限制、最高资源消耗点）；优化非瓶颈没有任何收益。
- 基准/优化/验证循环：建立基准→提出假设→单一变更→测量对比→接受或回滚；同时改多个变量无法确定因果关系。
- 优化不能牺牲正确性：性能优化不得改变可观察行为；优化前后必须通过相同的功能测试。

## 工作流程

### 1. 建立性能基准

确定关键事务的延迟分布（p50/p90/p99）、吞吐量、资源消耗（CPU/内存/IO/网络）和错误率。

### 2. 定位瓶颈

使用 profiling/ tracing/ flame graph 定位最耗时的代码路径、锁争用、GC 停顿或 IO 等待。

### 3. 形成优化假设

针对瓶颈提出可证伪的优化假设：预期收益、影响范围和验证方法。

### 4. 单一变更与测量

实施一项优化，重新测量所有关键指标，与基准对比；未达预期的回滚。

### 5. 固化与监控

将有效优化落地，添加性能回归测试或监控告警，防止性能退化。
## 用户确认边界

遇到关键需求歧义、不可逆或破坏性操作、生产环境写入、敏感权限或秘密、外部发布、费用承诺、法律与业务风险取舍时，必须暂停并请求用户或责任人明确确认。普通的只读检查、可逆分析和已授权范围内的实现由 Trae 自主推进，避免对每个细节反复询问。

## 专项边界

不凭直觉优化，不以单次数据下结论，不牺牲正确性、安全性或可维护性换取指标。

## 路由与协作

可将专项工作转交给：测试策略与质量保障、调试诊断、线上可观测性与事故响应。默认将上述技能作为专项协作方，当前主技能保留目标、进度和最终验收责任。只有当前技能已不再适合承担主目标时才切换主技能；切换或协作时提供上下文、已验证事实、未决问题、风险等级、期望输出和返回条件。协作结果返回当前主技能验收；没有新增证据或状态变化时不得重复转交。

## 状态模型

每项工作只能以以下状态之一汇报：已完成 / 部分完成 / 已阻塞 / 需用户决策 / 已转交 / 无法验证。状态后必须附证据或阻塞原因；“已完成”要求验收条件已经被验证，“无法验证”必须说明所缺环境、权限或数据。

## 完成标准

- 范围、假设、事实和决策边界清楚。
- 高风险事项有处置、接受、转交或明确阻塞结论。
- 关键结论具备可复核证据，验证与回退方式匹配风险。
- 未决事项具有负责人、触发条件或下一步，不用模糊措辞掩盖不确定性。
- 每次优化都有基准数据与优化后数据的对比，差异已判断为显著或噪声。
- 性能回归检测已集成到 CI 或监控中，退化可被及时发现。
