# APK编译问题诊断

## 定位与边界
本技能处理 Android 构建的诊断闭环，不把固定版本、阈值或命令当作通用答案。工具、命令、监控方式和实验顺序由 Trae 根据项目配置、设备资源、历史耗时和失败证据决定。

- 工具链缺失或需系统级安装：转 **Android开发环境搭建**。
- 一般跨生态编译：使用 **自动编译**。
- 根因超出构建系统、涉及复杂运行时或性能问题：转 **调试诊断**。
- 根因已明确且需改代码：携带证据转 **Bug修复**。

## 输入与先查后问
优先读取失败命令、完整日志、构建脚本、wrapper、插件与 SDK 配置、环境信息、最近变更及可复现条件。能从项目和环境查到的信息不询问用户；只有缺失信息会改变诊断方向时才追问。

## 诊断循环
1. **建立基线**：确认实际项目结构、项目声明的 JDK/Gradle/AGP/SDK 约束、可用空间与内存、网络和代理状态。环境版本以项目配置和兼容关系为准。
2. **复现并观察**：选择最小充分的构建目标，保存命令、日志、退出状态、产物和资源变化。超时及无进展判断应结合历史耗时、当前阶段、网络活动和资源指标动态确定。
3. **建立假设台账**：按证据排序网络、环境兼容、资源、缓存、配置和代码/资源错误等假设，记录预测与反证条件。
4. **可解释实验**：每次实验尽量只改变一个可独立解释的因素；彼此独立的只读检查可以并行。优先可逆、局部且不会污染环境的实验。
5. **验证根因**：修正后重跑原失败路径，并做与风险匹配的相关验证。成功一次不自动等于根因已证实，应确认结果与假设预测一致。

## 证据状态
- **已证实**：可重复证据支持，修正后原失败路径恢复。
- **高概率**：多项证据一致，但尚缺决定性验证。
- **待验证**：有合理预测，尚未完成实验。
- **已排除**：观察与预测冲突。
- **信息不足**：无法安全缩小范围。

不以固定重试次数决定停止。重复实验不再增加信息、需要越权安装/破坏性清理、或需要用户业务/架构取舍时停止并转交。

## 交付
报告失败类别、最小复现、根因状态与证据、实际变更、构建/产物验证、残余风险和下一步。

## 返回与闭环
诊断结果必须返回调用本技能的主技能或直接请求方。若构建任务由 `自动编译` 主持，则由其在可比环境中重跑原构建命令；仅“根因已定位”不能算构建问题解决。根因涉及环境时协作 `Android开发环境搭建`，涉及代码时协作 `Bug修复`，两者完成后都返回原构建主技能复验。完成状态使用“已完成 / 部分完成 / 已阻塞 / 需用户决策 / 已转交 / 无法验证”。
