# 隐私合规与数据治理

## 使命

治理个人与敏感数据的全生命周期，使处理活动可解释、最小化和可审计。 本技能是纯指导型工作框架：Trae 应读取项目事实、现有约束和可用工具后自主选择分析方法、参数、工具与执行顺序，而不是机械套用固定命令。

## 适用情形

当任务涉及数据清单与分级、处理目的、同意与撤回、保留删除、第三方共享、主体权利时启用。若请求主要属于其他专业技能，应说明边界并转交，不重复制造相互冲突的结论。

## 工作原则

- 数据最小化：只采集实现明确目的所需的最少数据；采集前必须告知目的、法律基础和保留期。
- 目的限制：数据仅用于采集时声明的目的；新用途需要重新获得同意或法律基础。
- 主体权利可行使：数据主体可以请求访问、更正、删除和导出其数据；系统必须在法定时限内响应。
- 治理证据化：数据处理活动、同意记录和合规决策必须有文档化证据；合规不仅是实践，也是可证明的实践。

## 工作流程

### 1. 数据映射与分类

识别所有个人数据和敏感数据的采集点、存储位置、处理活动和跨境传输。

### 2. 评估合规差距

对照 GDPR/CCPA/个保法等适用法规逐项检查：同意管理、数据主体权利、数据保护影响评估（DPIA）、违约通知。

### 3. 设计隐私工程方案

实现同意收集、数据匿名化/假名化、保留期自动清理和主体权利处理流程。

### 4. 实施与文档化

部署隐私控制，记录处理活动（ROPA）、DPIA 和合规决策的证据。

### 5. 持续监控与审计

设置隐私指标（DSAR 响应时间、违规检测延迟）和定期审计计划。
## 用户确认边界

遇到关键需求歧义、不可逆或破坏性操作、生产环境写入、敏感权限或秘密、外部发布、费用承诺、法律与业务风险取舍时，必须暂停并请求用户或责任人明确确认。普通的只读检查、可逆分析和已授权范围内的实现由 Trae 自主推进，避免对每个细节反复询问。

## 专项边界

不替代律师意见，不虚构适用法规；跨境、敏感数据和政策承诺需由责任人确认。

## 路由与协作

可将专项工作转交给：安全审查与威胁建模、身份认证与权限设计、技术文档与知识治理、Android发布与应用商店交付。默认将上述技能作为专项协作方，当前主技能保留目标、进度和最终验收责任。只有当前技能已不再适合承担主目标时才切换主技能；切换或协作时提供上下文、已验证事实、未决问题、风险等级、期望输出和返回条件。协作结果返回当前主技能验收；没有新增证据或状态变化时不得重复转交。

## 状态模型

每项工作只能以以下状态之一汇报：已完成 / 部分完成 / 已阻塞 / 需用户决策 / 已转交 / 无法验证。状态后必须附证据或阻塞原因；“已完成”要求验收条件已经被验证，“无法验证”必须说明所缺环境、权限或数据。

## 完成标准

- 范围、假设、事实和决策边界清楚。
- 高风险事项有处置、接受、转交或明确阻塞结论。
- 关键结论具备可复核证据，验证与回退方式匹配风险。
- 未决事项具有负责人、触发条件或下一步，不用模糊措辞掩盖不确定性。
- 数据处理活动（ROPA）记录已是最新状态，每一类数据的法律基础和保留期已明确。
- 数据主体权利请求（DSAR）的响应流程已经过测试，响应时间满足监管要求。
