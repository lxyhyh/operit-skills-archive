# 功能实现

## 开始条件
读取项目约定、相关代码、测试与现有规格，明确目标、非目标和验收标准。能通过代码与文档消除的疑问先自行查证。

- 普通实现细节、可逆局部设计和工具选择由 Trae 自主决定。
- 若歧义会改变业务范围、公开接口、数据模型、安全/权限边界、费用或关键架构取舍，请用户决定。
- 需求仍不足以形成可验证行为时，转 **追问引擎** 或 **需求追问文档**。

## 实施
1. 选择贯穿必要层级的**最小可交付行为切片**，先交付可观察价值，避免按数据库/后端/前端水平铺开。
2. 识别稳定 seam 和风险点；适合时使用 **TDD开发**，不为满足形式而测试实现细节。
3. 渐进实现。具体工具、文件顺序和技术细节由 Trae 依据代码库决定。
4. 每个切片完成后执行最小充分验证；范围由行为风险、项目约定和变更影响决定，可包括相关测试、类型检查、静态检查、构建或冒烟验证。
5. 审查需求覆盖、兼容性、安全、错误处理、文档和无关改动。

## 用户确认门
以下操作前展示方案、影响和回退方式并等待明确确认：改变公开 API、持久化结构、权限模型或关键架构边界；删除/迁移用户数据或大范围重写；新增付费服务、敏感凭据或生产操作；创建提交、推送、发布、合并或关闭 Issue/PR。除非用户明确要求，不自动提交或推送。

## 交付与状态
输出已完成行为、实际改动、验证证据、未完成项、已采用假设、风险与后续切片。状态使用"已完成 / 部分完成 / 已阻塞 / 需用户决策 / 已转交 / 无法验证"。部分完成不得包装成全部完成。

## 切片停止与返回
- 当前切片的验收标准全部通过才算该切片完成。
- 需求不清时停止实现，转交追问引擎或需求追问文档，不擅自补造行为。
- 实现完成后返回触发它的 Issue、PR、审查或主任务，按原验收标准复核。
- 审查发现的问题按严重度处理：影响当前验收、正确性、安全或兼容性的 Blocker/High 问题会撤销当前切片的完成声明；非阻塞建议可进入后续切片。
