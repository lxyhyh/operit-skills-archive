# 知识洁癖

## 定位
本技能是项目知识审计与同步编辑器：发现过期、冲突、重复、缺失和受众错位的信息，给出证据、严重度与路由。默认不把审计变成大范围整改；具体编辑方式由 Trae 根据项目结构和授权决定。

## 知识层与受众
- **代码和配置**：当前行为的主要证据，但仍需结合运行结果和外部契约判断。
- **项目代理说明**：供当前项目中的 AI 使用，保留硬边界、命令速查、权限与协作规则，不写流水账。
- **README/docs**：面向开发者、使用者和运维者，说明如何使用、系统如何工作及如何排障。
- **持久记忆（若平台提供）**：保存跨会话偏好、非显然教训和指向权威文档的索引；不假设固定路径。
- **版本历史/变更日志**：承载事件和演进过程，不把历史叙事堆入规则手册。

同一事实可面向不同受众表达，但应有明确权威来源，避免复制后各自漂移。稳定的系统知识应“毕业”到 docs 或项目说明；松散记忆保留必要指针或按平台能力清理。

## 触发条件
里程碑、交接、跨项目接口变化、架构/权限/环境变化、文档明显膨胀、发现旧事实误导执行，或用户主动要求审计时运行。

## 审计流程
1. **确定范围**：识别本次涉及的项目、下游消费者、可用记忆和项目约定。范围不清且会导致批量操作时请用户决定。
2. **盘点**：枚举相关根目录说明、README、docs、ADR、runbook、交接材料及可用记忆；记录“已评估 / 待改 / 不适用”，避免只检查最显眼文件。
3. **证据核对**：用代码、配置、测试、运行结果和当前决策验证路径、命令、API、环境变量、数据模型、权限和状态描述。
4. **问题分类**：标记过期、冲突、重复、缺失、位置错误、断链、不可验证或上下游不同步。
5. **严重度排序**：
   - 严重：会造成数据/安全风险、错误操作或外部契约破坏；
   - 高：会让后续开发或运维采用错误前提；
   - 中：增加理解和维护成本；
   - 低：措辞、结构或可发现性问题。
6. **制定最小同步**：优先就地更新权威来源、合并重复、删除或迁移失效内容，并修正指针。多个方案中优先变更小、易验证、易回滚者。
7. **验证**：检查链接和引用、命令/路径真实性、术语一致性、上下游文档及相对时间；比较修改前后，确认没有删除仍有效的约束。

## 膨胀与毕业判断
不采用对所有项目都相同的硬编码行数。结合平台加载限制、文件职责、检索效果、重复率和实际可读性评估：
- 规则手册若被历史叙事淹没，将事件迁往 changelog/history；
- 记忆若主要描述稳定机制，将内容并入权威文档并保留短指针；
- 单文档承担多个受众或主题时，按消费方式拆分并建立索引；
- 新信息若修正旧事实，编辑旧条目而非继续追加。

## 自主边界与确认门
只读审计、问题分类、差异建议可自主完成。用户已授权范围内的少量可逆编辑可由 Trae执行。批量移动/重命名/删除、跨项目大范围重写、改变外部承诺、清理持久记忆或无法判断哪项事实有效时，先列出映射、影响和回退方式，请用户决定。

## 路由
- Obsidian 结构、标签和双链整理：**知识库管理**。
- 术语与业务边界冲突：**领域建模**。
- 架构问题本身需要整改：**架构改进**。
- 需要跨会话继续：**对话交接**。

## 停止条件
- 所有已识别的知识层不一致项均已分类排序并给出处置建议。
- 超出授权范围的变更已列出为"需用户决策"。
- 不追求形式统一而触发无价值的批量修改——每项修改必须有可验证的不一致证据。

## 协作返回
专项协作（知识库管理、领域建模、架构改进）完成后必须返回本技能进行一致性复验。协作方修改的内容可能引入新的不一致，不能假设协作后问题自动关闭。

## 输出
报告审计范围、证据来源、按严重度排列的问题、已做的最小同步、未处理项、风险和推荐路由。状态使用“已完成 / 部分完成 / 已阻塞 / 需用户决策 / 已转交 / 无法验证”。“已完成”表示约定范围已审计和验证，不代表整个知识库永久无问题。
