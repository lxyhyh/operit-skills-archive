# CI-CD与发布管理

## 使命

设计可靠、可审计且可回滚的持续集成、交付和发布治理方案。 本技能是纯指导型工作框架：Trae 应读取项目事实、现有约束和可用工具后自主选择分析方法、参数、工具与执行顺序，而不是机械套用固定命令。

## 适用情形

当任务涉及流水线阶段、质量门禁、制品可信、环境晋级、变更审批、灰度与回滚时启用。若请求主要属于其他专业技能，应说明边界并转交，不重复制造相互冲突的结论。

## 工作原则

- 管道即代码：CI/CD 配置必须版本化，与源代码同仓库管理；环境差异通过配置注入，不在管道脚本中硬编码。
- 不可变制品：同一 Git SHA 优先构建一次并提升同一制品到各环境；平台限制不允许时记录构建可复现性证据。
- 渐进交付：部署策略（蓝绿、金丝雀、滚动）必须匹配风险等级；高风险变更必须有自动回滚或流量切换能力。
- 秘密零泄漏：密钥、证书、Token 不得出现在管道日志、构建产物和环境变量导出中；使用密钥管理服务和密封秘密。

## 工作流程

### 1. 分析项目构建与部署现状

扫描现有 CI 配置、构建脚本、部署方式、环境差异和秘密管理方式。

### 2. 设计管道

按触发条件（push/pr/tag/schedule）定义 stage：lint→test→build→security scan→deploy。

### 3. 构建与测试

在隔离环境中构建，运行单元/集成/E2E 测试；失败时管道中断，输出失败证据。

### 4. 安全扫描与门禁

对制品进行依赖漏洞扫描、SAST、容器镜像扫描；不符合阈值的阻断发布。

### 5. 部署与验证

按环境部署，运行冒烟测试和健康检查；异常时执行回滚或流量切换。
## 用户确认边界

遇到关键需求歧义、不可逆或破坏性操作、生产环境写入、敏感权限或秘密、外部发布、费用承诺、法律与业务风险取舍时，必须暂停并请求用户或责任人明确确认。普通的只读检查、可逆分析和已授权范围内的实现由 Trae 自主推进，避免对每个细节反复询问。

## 专项边界

不绑定特定平台，不绕过审批，不在未经授权时触发生产发布。

## 路由与协作

可将专项工作转交给：测试策略与质量保障、Android发布与应用商店交付、线上可观测性与事故响应。默认将上述技能作为专项协作方，当前主技能保留目标、进度和最终验收责任。只有当前技能已不再适合承担主目标时才切换主技能；切换或协作时提供上下文、已验证事实、未决问题、风险等级、期望输出和返回条件。协作结果返回当前主技能验收；没有新增证据或状态变化时不得重复转交。

## 状态模型

每项工作只能以以下状态之一汇报：已完成 / 部分完成 / 已阻塞 / 需用户决策 / 已转交 / 无法验证。状态后必须附证据或阻塞原因；“已完成”要求验收条件已经被验证，“无法验证”必须说明所缺环境、权限或数据。

## 完成标准

- 范围、假设、事实和决策边界清楚。
- 高风险事项有处置、接受、转交或明确阻塞结论。
- 关键结论具备可复核证据，验证与回退方式匹配风险。
- 未决事项具有负责人、触发条件或下一步，不用模糊措辞掩盖不确定性。
- 管道定义已版本化且与代码仓库一致；秘密管理机制已明确且无硬编码凭据。
- 回滚路径已经过演练（或已记录演练计划与阻塞原因）。
