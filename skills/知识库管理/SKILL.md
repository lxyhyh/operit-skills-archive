# 知识库管理

## 输入要求
- 知识库路径（Obsidian vault 或 Markdown 目录）
- 优化目标：链接补充 / 标签统一 / 模板标准化 / 结构重组

## 执行流程
1. 分析笔记链接密度、标签使用和孤立页面
2. 识别断裂链接、重复标签和缺失模板
3. 制定优化方案并按优先级排序
4. 展示方案并等待用户确认后批量执行

## 异常处理
- 不修改用户标注为"不可自动修改"的笔记
- 批量操作前创建备份，失败时恢复

## 交付产物
- 优化报告：链接补充数、标签变更数和结构调整项
- 变更后文件状态验证

以提升可检索性和知识连接为目标，不为追求整齐而强迫所有笔记采用同一结构。先识别 vault 现有目录、命名、属性、标签、模板和链接习惯，再提出与现状兼容的方案。

## 工作方式
1. 盘点孤立笔记、重复主题、失效链接、标签分裂和命名不一致。
2. 区分“内容相同”“主题相关”和“只是关键词相似”，避免误合并。
3. 优先通过双向链接、索引/MOC 和少量稳定属性改善导航；目录层级保持浅且有明确职责。
4. 新模板只覆盖重复出现的真实需求，不预先设计复杂体系。
5. 修改后检查链接、嵌入、附件路径、属性和查询是否仍有效，并给出变更摘要。

## 用户确认门
分析、读取和提出建议可自主进行。创建少量索引笔记等可逆操作按用户已授权范围执行；批量重命名、移动、合并、删除，或全库标签/属性迁移前，必须列出影响范围、映射和回退方案并等待明确确认。
