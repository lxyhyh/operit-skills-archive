# 技能路由
## 路由方法
先判断当前状态，而不只匹配关键词：目标是否清晰、是否已有代码库/规格/报错/根因、当前是探索还是执行、是否需要文档沉淀、是否存在事故止损或外部写操作。优先给出一个主入口、理由和预期产出；存在关键歧义时给一个备选及切换条件。

## 确定性裁决顺序
多项同时命中时，按以下顺序确定唯一主技能，后命中的作为协作方或后续阶段：
1. **安全与止损优先**：正在发生的数据损坏、安全事件、生产事故或不可逆风险，先用事故响应、恢复、安全审查或 Git 防护控制影响面；稳定后再回到原目标。
2. **用户明确入口优先**：用户指定技能时默认采用；若与当前证据或安全边界冲突，说明风险并给出替代或前置协作技能。
3. **当前阻塞优先**：选择能解除眼前阻塞并产生新证据的技能，而不是提前选择下游交付技能。
4. **证据阶段优先**：根因未知先诊断，根因明确再修复；需求未定先澄清/建模，规格明确再拆分/实现；报告与实施分阶段处理。
5. **目标产物优先**：候选仍相同时，选择直接拥有最终交付物和验收责任的技能为主技能，其他技能作为专项协作方。
6. **最小充分原则**：仍无法唯一裁决时，选择范围更窄、可逆性更高且最先产生判别证据的入口，并写明切换条件。

## 多意图任务
先拆成“当前主目标 + 后续目标 + 可并行协作项”。只有一个主技能管理整体状态；可独立且无写入冲突的专项工作可并行。若多个意图拥有不同不可合并的最终产物，则按依赖和风险排序分阶段路由，不把多个技能同时声明为主技能。

## 状态路由
- 不知道该用哪个技能：**技能路由**。
- 无代码库，想法或计划仍模糊：**追问引擎**。
- 有代码库且需严格追问并沉淀上下文/ADR：**需求追问文档**。
- 术语、边界、状态与业务规则不稳定：**领域建模**。
- 需要一次性验证设计问题：**快速原型**。
- 讨论已明确，要形成规格：**对话转PRD**；规格需拆成垂直任务：**计划转Issue**。
- 已有 PRD、Issue 或验收标准并要交付代码：**功能实现**；明确要求红绿重构：**TDD开发**。
- 已有报错且根因较直接：**Bug修复**；难复现、根因不明或性能回归：**调试诊断**。
- 通用项目构建：**自动编译**；Android 工具链缺失：**Android开发环境搭建**；APK 构建异常：**APK编译问题诊断**。
- Android 多角色协作：**Android角色协作开发**。
- Issue/外部 PR 分流：**Issue分类**；初始化其标签与文档约定：**技能初始化**。
- 代码模块边界设计：**代码设计**；扫描并推进架构改进：**架构改进**。
- Git 安全拦截：**Git防护**；提交前检查：**提交钩子**；冲突处理中：**合并冲突**。
- 测试类型断言迁移：**Shoehorn迁移**。
- 编写 Skill：**技能编写**；课程工作区：**教学**；练习目录：**练习搭建**；文章审校：**文章编辑**。
- Obsidian 笔记组织：**知识库管理**；项目知识审计与同步：**知识洁癖**。
- 上下文过长或需新会话继续：**对话交接**。
- **设计与数据**
  - API 契约、错误模型、版本兼容 → **API设计与契约治理**
  - 实体关系、索引、事务、迁移回滚 → **数据库设计与数据迁移**
  - 身份、会话、令牌、角色、最小权限 → **身份认证与权限设计**
- **质量与工程治理**
  - 独立审查代码、变更集 → **代码审查**
  - 测试分层、覆盖策略、质量门槛 → **测试策略与质量保障**
  - 依赖升级、漏洞许可、技术债务排序 → **依赖升级与技术债治理**
  - 性能基线、剖析、回归防护 → **性能分析与优化**
- **安全与合规**
  - 威胁模型、攻击面、安全控制 → **安全审查与威胁建模**
  - 数据清单、处理目的、同意撤回 → **隐私合规与数据治理**
- **交付与运行**
  - CI 流水线、制品晋级、灰度回滚 → **CI-CD与发布管理**
  - Android 签名、商店政策、轨道发布 → **Android发布与应用商店交付**
  - 日志指标追踪、告警降噪、事故止损 → **线上可观测性与事故响应**
  - 备份策略、RPO/RTO、灾难恢复演练 → **备份恢复与灾难恢复**
- **产品与体验**
  - 指标树、实验分流、因果推断 → **产品分析与实验治理**
  - 语义导航、本地化、辅助技术 → **无障碍与国际化**
  - 文档受众、信息架构、事实同步 → **技术文档与知识治理**

## 相邻技能消歧
- **Bug修复 vs 调试诊断**：是否已有可行动根因；没有则先诊断。
- **自动编译 vs APK编译问题诊断**：前者完成常规构建，后者针对已发生的 Android 构建异常建立证据链。
- **追问引擎 vs 需求追问文档**：是否需要结合代码库持续维护 CONTEXT/ADR。
- **知识库管理 vs 知识洁癖**：前者组织 Obsidian 结构，后者审计项目事实在代码、说明、文档和记忆间的一致性。
- **功能实现 vs TDD开发**：前者以交付为主并按需采用 TDD，后者明确以红绿重构循环为约束。
- **代码审查 vs Bug修复**：前者报告问题与严重度，后者执行修复；串联时先审查定位、再转修复、修后复核。
- **测试策略与质量保障 vs TDD开发**：前者制定整体测试计划和质量门槛，后者约束单个功能的红绿重构循环。
- **CI-CD与发布管理 vs Android发布与应用商店交付**：前者管理通用流水线和制品推进，后者处理 Android 特有签名、商店政策和轨道。
- **安全审查与威胁建模 vs 身份认证与权限设计**：前者评估全局威胁和攻击面，后者专项负责身份和授权体系设计。
- **性能分析与优化 vs 调试诊断**：前者针对可量化性能指标和对照实验，后者针对未知故障根因的逐步排除。
- **技术文档与知识治理 vs 知识洁癖**：前者负责文档生产和生命周期管理，后者审计项目信息在代码、文档和记忆间的一致性。

## 主技能协议
每个任务只指定**一个主技能**；其他技能为协作方，由主技能按需调度。主技能统筹目标、范围、状态和最终验收，并接收、验证协作结果。

### 主技能切换条件
- 任务核心目标已超出当前主技能的专项边界；
- 新证据表明需要另一领域的深度分析才能继续；
- 用户明确指定其他主技能入口。

切换时输出：切换原因、已获事实与证据、已排除项、当前阻塞、建议的新主技能及期望产出。

## 防循环与交接
记录已调用技能、已获证据和未解决问题。同一状态不得无新增证据地来回转交；若候选技能会返回当前技能，先明确切换条件。交接包含：目标、当前状态、已知事实与证据、已排除项、已做变更、待决策、风险、建议下一步。

## 路由输出格式
每次路由决策包含：
- 当前状态：任务目标、已有证据、未解决问题；
- 主技能：一个；
- 协作技能：零至多个，及调用条件；
- 选择理由与适用的裁决规则；
- 预期产物；
- 切换条件；
- 返回条件：协作结果如何验收。

## 路由完成
路由技能在完成导航后退出，不长期占据主任务。任务进入执行后由主技能接管状态管理。若任务已清晰且当前技能能够继续，不强制路由。
